# Inspección de reinicio y listeners nativos

Inspección de sólo lectura del 15 de octubre de 2026. No reinició ni cambió servicios, datos, credenciales, configuración de sistema o listeners. Fuente, restauración y carga no se tocaron. Detalles reproducibles y hashes de las fuentes oficiales: [`native-lifecycle-inspection.json`](native-lifecycle-inspection.json).

El CLI oficial 2.120.0 permite `stack restart` para el stack seleccionado usando su configuración guardada. No ofrece una opción por servicio. La [orquestación fijada a esa versión](https://github.com/supabase/cli/blob/v2.120.0/packages/stack/src/Orchestrator.ts) rechaza parar o reiniciar PostgreSQL con dependientes activos. El [runtime de PostgreSQL](https://github.com/supabase/cli/blob/v2.120.0/packages/stack/src/services/Database.ts) es dueño del proceso y de su socket Unix temporal. No se recomienda eludirlo con `pg_ctl restart` sobre ese proceso administrado.

La alternativa soportada para la prueba de persistencia es `supabase stack restart --workdir /tmp/zarix-runtime-20261015/e2e`, con `SUPABASE_HOME` aislado y salida privada. Afectaría sólo los cuatro servicios de ese stack E2E; conserva los datos, identidad, claves y puertos públicos según la [documentación del paquete](https://github.com/supabase/cli/blob/v2.120.0/packages/stack/README.md). Antes de ejecutarla se requiere liberar la ventana de pruebas de navegador. La evidencia posterior debe comparar PID y `pg_postmaster_start_time()`, huellas de datos/esquema/permisos y repetición del recibo mediante Auth normal. Este documento todavía no acredita ese reinicio ni ese replay.

El gateway público E2E escucha en `127.0.0.1:57321`, pero el PostgREST interno escucha en `*:27781`. Por ello no se afirma que todos los sockets nativos estén limitados a loopback. No se midió accesibilidad desde LAN ni reglas de firewall.

[PostgREST 16](https://docs.postgrest.org/en/v16/references/configuration.html#server-host) admite `server-host` / `PGRST_SERVER_HOST=127.0.0.1`, pero no se puede recargar en un proceso existente. La [receta REST de CLI 2.120.0](https://github.com/supabase/cli/blob/v2.120.0/packages/stack/src/services/Rest.ts) no expone host o entorno adicional, y el [launcher](https://github.com/supabase/cli/blob/v2.120.0/packages/stack/src/runtime/native-launcher.ts) hereda sólo PATH, HOME, temporales y locale. Una variable PGRST en el shell no llega al servicio. No se encontró un ajuste soportado por ese CLI para restringir el listener interno conservando el stack existente. No se alteraron binarios, caché, state.json, firewall ni TCC para sortearlo. HTTPS y aislamiento de red de producción siguen sin acreditarse.

La ejecución posterior autorizada se registra por separado en [e2e-stack-restart.md](e2e-stack-restart.md); este documento conserva su observación previa sin reinterpretarla.
