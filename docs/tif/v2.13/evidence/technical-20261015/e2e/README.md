CU002 creó cuentas por UI, verificó aislamiento y denegación por superar el límite Free con cuentas previas, mantuvo lectura/exportación y restauró Premium sintético. CU001 creó un gasto por UI y comprobó saldos 10000→8500→8000→10000 al editar/eliminar por API normal; diez reintentos de transferencia generaron un efecto y un recibo durable. CU003 contrastó el total visible 8000 ARS con todas las filas del usuario en el período controlado, incluidas las de intentos anteriores. CU004 compró una posición manual de 10 unidades a 100 USD con precio 110 por UI, vendió 4 unidades a 120 USD por UI y confirmó 6 unidades y 80 USD realizados; rechazó vender 7 y simuló 660→726/0 sin cambiar cuentas, movimientos, posiciones ni ventas.

La [proveniencia de proveedores](ui/provider-provenance.json) distingue las referencias financieras sintéticas del widget Mercados. `/api/market-data` utiliza URLs públicas hardcoded de CoinGecko, Yahoo y Stooq o su caché; no comparte las tres URLs configurables del doble HTTP503 de cotizaciones. Las capturas muestran lecturas públicas incidentales, no precios simulados de ese widget. No se registró un contraste independiente por proveedor que permita afirmar aceptación formal de esas integraciones. La posición FOOFIX y el libro financiero siguen siendo fixtures sintéticos; no hubo broker, operación bursátil, secreto externo ni cobro real.

La API conserva un [recibo para reintento](api/durable-replay-fixture.json) sin sesión, contraseña ni token: el reintento tras reinicio necesita una prueba separada del reinicio real. La pérdida del primer acuse de API es controlada por el cliente lógico del test y no demuestra una pérdida real de red. Cola offline, reinicio, perfil de carga y submatriz visual tienen runners y evidencias independientes; no se dan por ejecutados en esta carpeta.

Se conservaron los fallos del harness: [intento1](ui-attempt-1/e2e-verification.json), [intento de env](ui-env-attempt/e2e-verification.json), [intento2](ui-attempt-2/e2e-verification.json) e [intento3](ui-attempt-3/e2e-verification.json). El intento de env no alcanzó Auth/SQL: el wrapper inicial no retiraba las comillas del archivo privado; se corrigió la lectura en memoria. Los otros fallos fueron selectores observados en los formularios. [Primera corrección](ui-selector-fix/manifest.json) y [segunda corrección](ui-selector-fix2/manifest.json) registran hashes; el producto no se modificó para resolverlos. Sus fixtures permanecieron y el intento final pasó con fuentes estables.

Los comandos reproducibles, variables sin valores privados y guardas están en [docs/testing/isolated-e2e.md](../../../../../testing/isolated-e2e.md). Se ejecutaron con Node 22.17.0, Playwright 1.64.0 instalado temporalmente fuera del producto y `psql` nativo. El fixture de login y el secreto cron permanecen fuera del repositorio, con permisos 0600. Los reportes y las capturas contienen exclusivamente datos sintéticos, rutas/status/hash y no incluyen cookies, JWT, contraseñas, claves ni capacidad de invitado.

La observación mensual CNF-02, la equivalencia con infraestructura desplegada, HTTPS/cifrado de instancia y las integraciones reales Gemini/OCR/Telegram/Mercado Pago requieren evidencia propia. Firefox/Edge no están instalados; Safari no se infiere de WebKit ni de metadata MCP. Las cuatro capturas de escritorio no completan la matriz visual ni la compatibilidad de navegador.
